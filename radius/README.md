# Isolated RADIUS experiment — not ready for a physical test or production

This branch is based on main `75c5399d2da1e062e5dfece532475c77f588ab64`. FreeRADIUS 3 handles packets and `adapter.py` is an `rlm_exec` HMAC bridge to Laravel's internal policy endpoints. The checked-in server binds **only loopback**; no deployment, production traffic, provider payment, or router changes have been performed. Packet tests use a simulator, not a live Laravel service. No physical MikroTik or end-to-end payment sandbox test has been performed.

## Implemented lab profile

* A newly redeemed, pre-issued voucher on a RADIUS router is marked with the session's original backend. Legacy/unknown and site-agent-origin sessions are not accepted as RADIUS sessions. Online-sale-linked vouchers are explicitly rejected despite the separate durable payment fulfillment changes: combined payment, RADIUS readiness, and refund/revocation behavior have not been established as safe. Do not use this branch to test real payments or assume its separate payment sandbox works end to end.
* Only one-device, uncapped packages are admitted. Post-password-auth policy calls lock the voucher and session and permanently reserve the entitlement to one NAS session ID and normalized MAC. Same identity can retry; different ID or MAC is rejected. Accounting Start must match the reservation and Interim/Stop must match the MAC and voucher. Retries are idempotent; quarantined or malformed accounting is not ACKed. Valid Stop closes the application session, so reconnect is not implemented.
* Reservation is deliberately **not** automatically released on timeout, failed packet delivery, or missing accounting: until the voucher's session expires, this may strand the voucher. Never clear it manually while an old device might be connected. MAC is NAS-reported and spoofable, not proof of physical device identity. Correctness under simultaneous requests on PostgreSQL/MySQL has not been tested; SQLite tests do not establish row-lock concurrency behavior. This mechanism does not stop NAS ID reuse or a malicious/compromised router impersonating a device.
* Forward backend opt-in checks outstanding work and new activations lock the router. Reverse transitions without reconciliation are unsupported. Known conflicting origin is blocked in voucher activation, RADIUS policy, revocation and operator device-ban path; this is not a complete audit of every backend-changing or site-agent command path. Existing sessions are not backfilled. Do not switch a real router's backend, edit the database to bypass guards, or run existing router provisioning scripts against this RADIUS lab.
* Voucher code is both User-Name and PAP/CHAP password, an intentionally weak existing convention, with no independent secret factor. FreeRADIUS verifies PAP/CHAP before calling policy; EAP, MS-CHAP and mixed methods are rejected. Require patched FreeRADIUS/RouterOS and `require_message_authenticator = yes`. One exact static client source IP, unique shared secret and client `shortname` equal to the provisioned NAS-Identifier are required per router. Reject wildcard clients and shared NAT. Classic RADIUS is not confidential; require private encrypted transport, and do not use real credentials in FreeRADIUS debug output.
* Access and accounting packets must supply exactly one NAS-Identifier, User-Name, Acct-Session-Id and Calling-Station-Id; accounting also needs status and a stable Event-Timestamp. Whether the intended RouterOS version supplies these in Access-Request and across accounting/retries is unknown. Missing attributes fail closed. Verify against a dedicated physical device before claiming compatibility; do not invent IDs/timestamps. Session-Timeout and symmetric Mikrotik-Rate-Limit are emitted, but physical enforcement is unverified.
* No Disconnect/CoA sender, delivery/retry worker, or confirmed revocation exists. See `DISCONNECT-TRANSPORT-EVIDENCE.md` for the separate loopback transport simulator and the queue/identity blockers. No immediate enforcement of voids, bans or other changes is possible. Disconnect delivery acknowledgement is not a confirmed Stop. The lab rejects capped packages and blocks the RADIUS device-ban path, but does not provide a substitute. Accounting outages, lost Stop, timestamp ordering, duplicate event and gigaword behavior need end-to-end and real-router tests. Synchronous per-packet exec, 2-second API timeout, endpoint throttling, no spool/queue, no load/availability evidence and no monitoring are significant limitations.

## Setup and trust boundaries

Use disposable, isolated synthetic-only infrastructure. Do not use production data, networks, routers or credentials. A trusted operator must securely transfer each generated one-time router RADIUS secret to the corresponding FreeRADIUS client and router; there is no automatic secret sync or supported rotation/recovery. Use a separate 32-byte-or-longer service HMAC secret, protected config file and service account. HTTPS certificate verification is mandatory except explicit loopback HTTP below. The adapter disables proxy environment forwarding and redirects. Configure Laravel's HMAC secret, direct-peer source allowlist, shared atomic nonce store, accurate clocks, protected HTTPS and network isolation; see `docs/RADIUS-POLICY-CHANNEL.md`. Do not expose these endpoints publicly.

For local simulation only, use a protected JSON file such as `{"base_url":"http://127.0.0.1:8000","allow_loopback_http":true,"service_secret":"REPLACE_WITH_A_SEPARATE_32_BYTE_OR_LONGER_SECRET"}`. `radius/freeradius/mods-enabled/wifi` contains paths that must be changed to protected absolute paths. An exact example client, with all placeholders replaced:

```
client router_lab {
    ipaddr = 127.0.0.1
    secret = REPLACE_WITH_THIS_ROUTERS_GENERATED_SECRET
    shortname = REPLACE_WITH_EXACT_PROVISIONED_NAS_IDENTIFIER
    require_message_authenticator = yes
}
```

Use an isolated copy of stock raddb with only required modules (`pap`, `chap`, `always`, `wifi`), no stock default clients and only the supplied virtual server. Validate with `freeradius -XC -d <isolated-raddb>`; do not alter the system server. The client source and network setup required to move beyond loopback are intentionally not provided as an operational router recipe.

## Tests

`python3 -m unittest -v radius/test_adapter.py` runs HMAC bridge tests against a loopback API simulator. `python3 radius/test_packets.py /path/to/readable/stock/freeradius/3.0` copies the stock configuration to a disposable temporary directory, starts a loopback FreeRADIUS and simulator, and uses `radclient` plus a raw packet. It checks PAP/CHAP password verification, client/NAS binding, missing session/Message-Authenticator, wrong secret, mixed MS-CHAP, policy rejection/API failure and accounting Start/Interim/Stop and no ACK on failures. The tests use throwaway secrets, not actual Laravel or a real router. Laravel feature tests separately exercise the policy and lifecycle on SQLite in memory; neither tests real row-lock races nor external infrastructure.
