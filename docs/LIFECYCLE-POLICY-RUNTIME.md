# Lifecycle policy runtime notes

Lifecycle state is evaluated independently for suspended, KYC pending/rejected, past due with a past subscription end, and trial with a past trial end. Any applicable denial wins. A past-due or trial state with no end timestamp is not treated as expired by the existing state resolver.

For each applicable state/action, an explicit boolean policy row takes precedence. If no row exists, the policy-center catalog's boolean default applies; a `null` default means no restriction for that state/action unless an explicit row exists. Thus KYC-pending billing, for example, is not implicitly denied. A malformed explicit value is not permission. A policy-storage read failure denies actions for tenants with an applicable restricted state, even if a previous read allowed them. Tenants with no applicable state do not need to read lifecycle policy storage. Reseeding inserts missing policies but does not overwrite operator changes.

The dashboard, analytics, site metrics and site-metrics export, and billing routes now enforce their corresponding lifecycle actions; existing sell, redeem, voucher-generation and withdrawal checks remain. An HTML denial redirects only an admin/finance user to billing when billing is allowed; otherwise it returns 403. JSON denials return 403. Platform administration and account recovery/security routes are not gated by these operator lifecycle checks. Billing is a view, not a connected subscription checkout.

`view_reports` is not a comprehensive data-classification boundary: other operational pages and the dashboard may contain metrics or transaction data, and customer export is an operational data export. This change does not purport to block every source of reporting information. Likewise these action policies are not a blanket suspension of every operator operation. Expand coverage only after defining those product semantics.

Policy changes are audited even when optional auditing is disabled. Changes and mandatory audit writes use the same database transaction, including the legacy policy endpoints. Legacy endpoints require the existing recent-MFA middleware, as does the policy center; their existing response/form contracts remain. General policy reads outside lifecycle still use `Policy::get`'s existing cache and caller-supplied fallback behavior; this change does not make all security/financial policy storage failures fail closed.
