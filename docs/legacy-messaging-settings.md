# Legacy platform messaging settings

The platform configuration email and SMS save actions store newly entered SMTP passwords and SMS API keys encrypted with Laravel's application key. Empty or omitted secret fields retain the current value; there is no clear-secret action. Existing plaintext values remain readable and are not migrated or rewritten automatically. Replace each value to encrypt it. Keep and back up the application key securely: changing or losing it prevents decryption of encrypted credentials. The shared legacy `getSecret` fallback cannot distinguish a plaintext value from ciphertext encrypted under an unavailable key.

Email and SMS tests use only the currently saved settings. Save changes before testing; the test endpoints reject nonempty configuration fields instead of silently saving or ignoring them. They can send real messages and update the saved connection status. As with other sensitive platform actions, recent MFA is required when the application's step-up policy is enabled. If the policy or deployment-level step-up switch is disabled, the existing middleware permits the action without step-up.

Delivery failures intentionally omit raw provider responses and exception messages, which might contain credentials. SMS service responses no longer return raw provider response data or provider-specific error details. Investigate issues through the provider's dashboard rather than copying credentials into logs. SMTP/SMS changes should be verified in an appropriately controlled environment; automated tests here use in-memory SQLite and fake transports.
